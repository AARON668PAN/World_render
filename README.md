# G1 橘子任务上真机包

Unitree G1 + Dex3 三指手，官方 GEAR-SONIC 控制器（**默认版**）。学生看头部相机画面和关节角，每秒 50 次给控制器发
"64 维 token + 两只手各 7 个手指角"，消息格式和 NVIDIA 自己的 VLA 客户端逐字节相同。**不给指令机器人不动。**

两句指令（只认这两句）：

- `put the orange on the plate`
- `put the orange back on the table`

**2026-11-19 这一版（学生 `ditrn_op_r1`）建议只做第一句。**第二句只在机器人站得靠前、落点不远时可靠，原因和成绩见第 7 节。

## 1. 谁跑什么

| 电脑 | 跑什么 |
|---|---|
| 机器人上的电脑 | 官方 `gear_sonic_deploy`（默认版 SONIC）和官方相机服务。本仓库不改它、也不带它的权重 |
| 一台带 NVIDIA 显卡的电脑，和机器人同一网段 | 本仓库：学生 + 客户端 |

学生要跑在显卡上：RTX 5090 上一次规划约 35 ms（接假机器人整局实测中位 52 ms）。8 线程 CPU 上是 180~320 ms，客户端上限 240 ms，余量不够。

## 2. 学校电脑上第一次安装

```bash
git clone -b g1-head-cam-align --single-branch git@github.com:AARON668PAN/World_render.git g1_orange_plate_deploy
```
```bash
cd g1_orange_plate_deploy && ./setup_env.sh
```
```bash
./assemble_weights.sh
```
```bash
./run_selftest.sh
```

学校电脑上已经有这个仓库的话（2026-11-19 这一版在分支 `g1-head-cam-align` 上），更新后要重新拼权重、重新自检：

```bash
git pull
```
```bash
./assemble_weights.sh
```
```bash
./run_selftest.sh
```

`git pull` 之前先看一眼 `git branch --show-current`。显示的不是 `g1-head-cam-align`（比如还是旧分支 `g1-orange-plate-deploy`）就先切过去：

```bash
git remote set-branches --add origin g1-head-cam-align && git fetch origin && git checkout g1-head-cam-align
```

自检通过后核对一下版本：`git log -1 --format=%s` 应以 `README: clone` 开头，`cat student/model.sha256` 应以 `bda6dc9f` 开头。

- `setup_env.sh`：在 `.venv` 里装 Python 3.12 的环境（有 `uv` 用 `uv`，没有用 `python3.12 -m venv`）。
- `assemble_weights.sh`：学生权重 627 MB，GitHub 单个文件上限 100 MB，所以切成 7 段放在 `student/` 里；这一步把它们拼回 `student/model.safetensors` 并核对校验值。
- `run_selftest.sh`：不需要机器人。它检查三件事：权重每一个数都和文件一致；固定输入下算出的数和训练机上一样；
  假机器人整套收发（没指令时 0 条动作消息，做的时候稳定 50 Hz）。最后一行是 `ALL_SELFTESTS_DONE` 才算过。
- 加载学生不联网：文字编码器和图像网络的权重都在 `student/model.safetensors` 里，分词器的小文件在 `assets/`。

## 3. 上机前必须确认

| 事 | 怎么确认 |
|---|---|
| 控制器是**默认版** SONIC | 启动命令里不能有 `--cp policy/sonic_v1_1/...`。v1.1 的 token 含义不同，C++ 不报错，机器人会乱动。默认版两个文件的 SHA-256：`model_encoder.onnx` 以 `013ab0287236aa27` 开头，`model_decoder.onnx` 以 `c7241a123eaa36b5` 开头（仿真用的权重已和它逐位比过，一致） |
| 手指电机顺序 | `ROBOT_IP=<机器人 IP> ./run_client.sh --hand-check`，用手掰一根手指，看哪一项在变；食指、中指反了就加 `--hand-order middle_first` 或 `index_first` |
| 头部相机 | 学生是按机器人头上自带的 D435i、**1280x720（16:9）**、相对躯干下倾 63° 的画面训的（脖子量完别再动）。**机器人上的相机服务必须发 1280x720**：把 GR00T-WholeBodyControl `gear_sonic/camera/drivers/realsense.py` 里的 `color_image_dim` 改成 `(1280, 720)`，重启相机服务。还在发 640x480 的话画面是中间一块放大的，客户端会拒绝指令并提示 `camera WRONG SHAPE 640x480`（`ready` 抬手不受影响）。实测参数和对齐工具见 [`camera_align/`](camera_align/README.md) |
| 场景摆放 | 见下 |

摆放（量桌子近边和机器人脚尖，不量骨盆；图见 `docs/setup_layout_put_into_plate.png`）：

- 桌面高 74 cm（训练里 72~77.5 cm），桌板最多 3 cm 厚。机器人正对桌子，**站正、左右居中**，脚尖离桌子近边 11~12 cm（训练里 7~13 cm）。
- 盘子（灰色，直径约 18 cm）中心：离桌子近边 10 cm，在机器人正中偏左 4 cm。
- 橘子（直径约 7.8 cm）：**离桌子近边 10 cm，在机器人正中偏右 19 cm**（仿真里 3 种站法 24/24）。示范视频里的位置是离近边 11 cm、偏右 13 cm，也在训练范围内，仿真里 19/24。
- 背景尽量和拍示范视频时一样（白桌、素墙）。

## 4. 上机步骤

机器人吊着或有人扶，第一次一定这样。

1. 机器人上（官方部署终端），默认版：
   ```bash
   cd gear_sonic_deploy && ./deploy.sh --input-type zmq_manager --zmq-host <跑学生那台电脑的 IP> real
   ```
   回车确认后机器人到默认站姿等待。**这个终端里之后只碰 `O`（急停，机器人会瘫软）**。别的键会被转发：回车会切到预置
   参考动作，`T` 会播放它（里面有舞蹈）。
2. 机器人上起官方相机服务：
   ```bash
   python -m gear_sonic.camera.composed_camera --ego-view-camera oak --ego-view-device-id <MXID> --port 5555
   ```
3. 学生电脑上，按这个顺序各跑一次（`GR00T_WBC` 指向官方 GR00T-WholeBodyControl 的代码目录，读官方相机流要用；
   用普通 USB 相机就设 `CAMERA=cv:0`）：
   ```bash
   ROBOT_IP=192.168.123.164 GR00T_WBC=<官方代码目录> ./run_client.sh --hand-check
   ```
   ```bash
   ROBOT_IP=192.168.123.164 GR00T_WBC=<官方代码目录> ./run_client.sh --dry-run
   ```
   ```bash
   ROBOT_IP=192.168.123.164 GR00T_WBC=<官方代码目录> ./run_client.sh --no-student
   ```
   ```bash
   ROBOT_IP=192.168.123.164 GR00T_WBC=<官方代码目录> ./run_client.sh
   ```
   - `--hand-check`：只读，核对手指顺序。
   - `--dry-run`：什么都不发，看相机、状态、学生延迟是否正常。
   - `--no-student`：学生不出手。`ready` 之后给指令，只核对并打印真机和仿真起始姿势差多少。**第一次离桌子远 30 cm 做，先看手的路线。**
   - 不带开关：正式做。
4. 在客户端里打字。桌子不用动，**机器人站的位置是硬规矩**：

   - **脚尖离桌沿 11~12 cm**（两只脚尖连线到桌子近边；训练数据里是 7~13 cm）。**站正、居中最要紧**：朝向歪 1.5 度以内、左右偏 1.5 cm 以内时仿真里 94%，否则 76%（训练范围是 ±3 度、±3 cm）。站着不动时骨盆中心离桌沿约 20 cm。比视频里靠后约 13 cm：再近的话，控制器自己的站姿手腕就卡在桌沿上了。
     （11-19 更正：这里原来写的是“脚尖前约 16 cm”，那个数是错的，按它摆会比训练时远 6 cm，手够不到。）
   - 盘子中心离桌沿 10 cm（盘边离桌沿约 1 cm）、偏机器人正中左侧 4 cm；橘子中心离桌沿 10 cm、偏右 19 cm（或示范视频里的位置：11 cm、偏右 13 cm）。
   - 机器人左右两侧各留 70 cm 空地，抬手时手臂要往两侧张开。
   - **桌子前沿的厚度决定手会不会碰桌子**（11-19 重新量过）：机器人站着等指令时手垂在身前，伸到脚尖前面 14~20 cm、离地 54~68 cm。脚尖离桌沿 10 cm 时，手伸进桌沿下面约 10 cm；桌面 74 cm 高的话，前沿（桌板加横梁）超过 3 cm 厚手就会顶在桌沿上（脚尖 13 cm 时是 5 cm 厚）。桌沿下面 20 cm 以内、离地 54 cm 以上不能有抽屉、横梁。仿真里手顶着桌沿（被推回 2~5 cm）也能正常抬手、不倒，但真机上没试过，注意三指手别卡住。

   | 顺序 | 打字 | 机器人 |
   |---|---|---|
   | 1 | `start` | 控制器自己站住（官方的 PLANNER 模式），学生没接上 |
   | 2 | `ready` | 11 秒：两臂侧平举 → 屈肘把前臂收到身前 → 上臂放下 → 落到起始姿势，然后一直停着 |
   | 3 | 两句指令之一 | 学生最多做 11.3 秒，做完 1.5 秒回起始姿势，继续停着 |
   | 4 | 再给指令 / `stop` | 可以连着做；`stop` 是中断并回起始姿势停着 |
   | 5 | `planner`，15 秒内再敲一次 | 11 秒按原路把手放下，再交还控制器站着 |
   | 6 | `quit` | 退出 |

   为什么绕两侧：机器人站着时手垂在离地约 56~68 cm 的地方，在桌面下面；直接往前抬会从下面顶到桌板，直接交还会把手压在
   桌面上。这条路线在物理仿真里跑过（SONIC 自己跟，8 局，桌子按 76 cm 高、8 cm 厚）：不碰桌子，橘子不动，上身最多后仰 5°，
   停稳后离训练起始姿势 0.08 rad 以内。手臂始终贴近身体：伸直手臂往正前方举会让它后仰 19°，试过，不用。
   **真机上没跑过。**第一次用：机器人再往后多站 30 cm 试一遍 `ready` 和 `planner`，看手的路线，再到位置上做。
   起始姿势本身是悬空的：左手最低点离地 80 cm，右手 85 cm。站着时的手和桌沿的关系见上面“桌子前沿的厚度”那一条。

   - 没先 `ready` 就给指令：拒绝。`ready` 只能在控制器站立模式下用。
   - 停着的时候 `quit` 会被拒绝。`quit!` 是不交还直接退出，控制器保持最后的姿势不动。
   - 客户端重启后机器人还举着手：敲 `hold` 接管当前姿势，不要敲 `start`（会被拒绝，因为它会让手直接放下）。
   - `status`；`estop` 等于官方急停（机器人瘫软，手会落在桌上）。

一条指令的过程（已经停在起始姿势）：0.5 秒对到这句指令的起始姿势 → 停 1 秒 → 核对姿势 → 学生最多做 11.3 秒 → 1.5 秒回
起始姿势停着。做完指令就清空，下一次要重新打字。每一局的记录存在 `logs/`。

## 5. 保护措施

客户端这边（C++ 那边对 token 不做任何检查）：

- 指令只认配置里的两句话。空的、别的话、正在做时再给，一律不动。
- 没先 `start`、收不到机器人状态或相机画面时，指令被拒绝。相机画面不是 16:9（比如还在发 640x480）也拒绝。
- 给指令的那一刻先量真机的手臂和腰：离起始姿势超过 0.35 rad 就拒绝，什么都不发（11-19 加的；以前只看客户端自己记的状态）。
- 学生开始前核对手臂和腰的角度，离示范起始姿势超过 0.35 rad 就不放学生（`--start-tolerance`）。
- 每条消息：有非数字就中止；学生的 token 限在 ±0.6（预先算好的抬手、放手 token 是 SONIC 编码器自己给的，会到 −0.625，放宽到 ±0.75）；手指目标限在关节范围内，每拍最多变 0.12 rad。
- 相机超过 0.5 秒或状态超过 0.2 秒没更新，中止并返回。
- 学生 0.5 秒没给出新计划，中止并返回。
- 从站姿抬手只能用 `ready`（绕两侧），放手只能用敲两次的 `planner`（原路退回）；学生做的时候一局结束、`stop`、相机或状态断了，都是回起始姿势停着，不自动放手。
- `ready` 抬到一半被 `stop` 或状态中断：手臂停在原地不动，不走近路去起始姿势（近路会穿过桌子）；这时指令和 `ready` 都被拒绝，敲两次 `planner` 从停下的地方原路退回，再重新 `ready`（11-19 加的）。`ready` 只看机器人状态，不看相机。
- 客户端退出或报错时不再把控制器切回站立模式（手会往下压桌子），控制器保持最后的姿势。

管不到的：

- 客户端进程被杀或断网时，C++ 会一直保持最后一个 token，没有超时。只能靠人按 `O`。
- 机器人会不会碰到桌子、会不会失去平衡，客户端不判断。它不知道桌子在哪，站位对不对全靠人摆。

## 6. 已知风险

1. **画面。** 学生对画面长相很敏感（第 7 节考试 1、4b）。真机头部相机的颜色、曝光、视角和训练画面差得多，就可能抓不到。
   先 `--dry-run` 看一眼相机画面，再决定要不要放学生。
2. **SONIC 的仿真到真机差距没测过。** 默认版 SONIC 跟手腕很差，老师是靠挪参考动作来补的；真机响应要是不一样，起始
   姿势就对不上，`--no-student` 那一步能量出来。
3. **"放回桌面"只在一部分摆法下可靠。** 这一版老师在机器人站得靠后或落点靠里时放不好（手臂够不着），这些示范没进训练集。先只做"放到盘子上"。
4. **手指力矩。** C++ 把手指目标限制在实际角度 ±0.25 rad、刚度 1.5，最大约 0.375 N·m。仿真按这个上限考，"放到盘子上"73%，和不加上限时一样（考试 5）。
5. 起始姿势只有一个：仿真里已考（4c、6），不是主要风险。
6. **站着等指令时手在桌板下面。** 控制器的默认站姿手在身前，脚尖 11~12 cm 时从 3 cm 厚的桌板下面伸过去，上下余量 1~2 cm。桌沿往里 20 cm、离地 54 cm 以上不能有抽屉、横梁。

## 7. 仿真成绩（2026-11-19，学生 `ditrn_op_r1`）

学生：从零训的 `dit_resnet`，30,000 步，214 条示范（"放到盘子上"153 条 = 17 个橘子位置 x 3 种站法各 3 条；"放回桌面"61 条），
v9 渲染的真机头部相机画面（D435i 1280x720、下倾 63°，每条示范的相机角度随机偏 ±3~4°），输出 64 维 token + 14 个手指角。
每种站法有自己的桌高（72~77.5 cm）、脚尖到桌沿距离（7~13 cm）、左右偏移（±3 cm）和朝向（±3°）。

| 环节 | 是谁的成绩 | "放到盘子上" | "放回桌面" |
|---|---|---|---|
| 老师验收（每个片段 32 局） | 老师 | 51 个片段全部 32/32 | 51 个片段里 21 个 ≥ 27/32，其余多为 0/32 |
| 考试 2：回放训练用的渲染画面（12 个片段 x 8） | 学生 | 49/64 = 77% | 22/32 = 69% |
| 考试 4a：真机方式起步，标准片段 x 32 | 学生 | 29/32 = 91% | 29/32 = 91% |
| 考试 4c：真机方式起步，另外 12 个片段 x 8 | 学生 | 47/64 = 73% | 20/32 = 62% |
| 考试 5：回放画面 + 手指力矩限到真手水平 | 学生 | 47/64 = 73% | 21/32 = 66% |
| 考试 6：真机方式起步，"放到盘子上"全部 51 个片段 x 8 | 学生 | 329/408 = 81% | 没考 |

怎么读：

- 这些考试里学生看到的是训练用的渲染画面，仿真物理是实时的。**这一版没有做"换装仿真"的画面考试**，真机画面和渲染画面的差别
  对它的影响没有量过（上一版学生换画面后从 89% 掉到 41%）。
- "放到盘子上"失败的全是橘子没抓起来，没有摔倒或打飞。
- 站得正不正影响最大：朝向歪 1.5° 以内且左右偏 1.5 cm 以内 105/112 = 94%，其余 224/296 = 76%。脚尖到桌沿的距离、桌高
  在训练范围内看不出趋势。
- 橘子偏右 19 cm 的那一列最稳（离桌沿 7~12 cm 的三个位置 72/72，离桌沿 15 cm 的 20/24）。示范视频里的位置（偏右 13 cm）19/24。
- "放回桌面"差在老师：参考动作要上身前倾 17° 去够，SONIC 实际只前倾 4~5°，机器人又比上一版靠后站，落点靠里或站得靠后时手臂
  伸直也够不着。这些片段的示范没进训练集。
- 抬手路线（`ready`）在物理仿真里跑过两个站位各 8 局：抬手过程不碰桌，上身从站立时前倾 7° 变成直立，停稳后离训练起始姿势
  0.03 rad。那次仿真用的是 6 cm 厚的桌沿，站着时手是顶在桌沿上的；3 cm 厚的桌板按几何算不碰（见第 6 节第 6 条）。

对照：上一版学生 `ditrn_op_v8tok`（固定站位、旧相机参数，不能用在这台相机上）考试 2 是 85/96 = 89%，4a 是 32/32 和 20/32。
